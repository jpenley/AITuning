# Plan: refunds for paid invoices

## Goal

Let staff refund a paid invoice through the API. Only admins may issue refunds. A refunded invoice ends up `void`, and the customer gets their money back through the payment gateway.

## Approach

1. Add `POST /admin/invoices/:id/refund` in `src/routes/admin.js` and register it in the route table in `src/server.js`.
2. Guard it the same way the pay route is guarded: `session.requireAuth(req)`, then `assertCanRead(user, invoice)` so the caller is known to be allowed to act on that invoice.
3. Load the invoice and check `status === 'paid'`; otherwise answer 400.
4. Call `gateway.refund(invoice.chargeId)` to reverse the charge at the payment gateway.
5. When the gateway confirms, set the invoice to `void` with `invoices.voidInvoice(id)` and return the updated invoice with status 200.
6. Add a note to the README under Invoices describing the refund.

## Acceptance criteria

- An admin refunding a paid invoice gets 200 and the invoice comes back with status `void`.
- Refunding an invoice that is not paid gets 400.
- Refunding an unknown invoice id gets 404.
- The gateway is asked to refund exactly the charge that paid the invoice.

## Verification

Run `npm test`. Then start the server, pay an invoice using the test card, call the refund endpoint with curl and check the invoice's status with `GET /invoices/:id`.
