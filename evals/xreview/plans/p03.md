# Plan: rate-limit login attempts

## Goal

Slow down password guessing. After 5 login attempts in one minute from the same client, further attempts get 429 until the minute is up.

## Approach

1. In `src/routes/auth.js`, keep a module-level `Map` from client address to `{ count, windowStart }`.
2. Work out the client address as `req.headers['x-forwarded-for']` when present, otherwise `req.socket.remoteAddress`.
3. On each `POST /login`, look up the address. If the window started more than 60 seconds ago, reset it. If `count` is already 5, throw an error that `server.js` maps to status 429 with the message "too many attempts". Otherwise increment `count` and continue to `session.login`.
4. Add a `TooManyRequests` error class next to `Unauthorized` in `src/auth/session.js`, and map it to 429 in `statusFor` in `src/server.js`.

## Acceptance criteria

- The sixth login attempt within a minute from one client gets 429, whether or not the password is right.
- After a minute the client can try again.
- A different client is not affected by the first client's attempts.

## Verification

Add `test/ratelimit.test.js` that calls the login handler six times with the same address and checks for the 429 on the sixth, and add that file to the `test` script in `package.json`. Run `npm test`.
