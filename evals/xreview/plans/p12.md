# Plan: log how long each request takes

## Goal

Some requests feel slow and there is no data. Print one line per request to standard output with the method, path, status and duration, so slow endpoints can be found from the logs.

## Approach

1. Add `src/util/timing.js` exporting `formatLine({ method, path, status, ms })`, which returns `"<METHOD> <path> <status> <ms>ms"` with `ms` rounded to one decimal.
2. In the request handler in `src/server.js`, take `process.hrtime.bigint()` on entry and register `res.once('finish', ...)` that computes the elapsed milliseconds and calls `console.log(formatLine(...))`. One listener covers the success path, the `catch` path and the early return for an unknown route.
3. Use only the path, without the query string (`req.url.split('?')[0]`), and never log headers or bodies: they can hold tokens and card numbers.
4. Add `test/timing.test.js` covering `formatLine`, and add that file to the `test` script in `package.json`, which lists its test files explicitly.

## Acceptance criteria

- Every request produces exactly one log line, including requests that fail with 401, 404 or 400.
- The line never contains the query string, a header or a body.
- `formatLine({ method: 'GET', path: '/invoices', status: 200, ms: 12.345 })` returns `GET /invoices 200 12.3ms`.

## Verification

Run `npm test`, start the server, make a successful, an unauthorised and an unknown request with curl, and check that each produced one line.
