# Plan: invoices in more than one currency

## Goal

Some customers are billed in EUR, GBP or JPY. Invoices should be created, shown and paid in their own currency, and staff should be able to see every invoice's total in USD.

## Approach

1. Add a `currency` field to invoices (`USD` by default, else `EUR`, `GBP` or `JPY`). `totalCents` stays in the invoice's own currency.
2. Add `src/services/fx.js` with `usdEquivalent(totalCents, currency)`: it fetches the current rate from the rate provider's `latest` endpoint, caches it for an hour, and returns `Math.floor(totalCents * rate)`.
3. Add a `totalUsdCents` field to the invoice representation returned by `GET /invoices` and `GET /invoices/:id`, computed with `usdEquivalent` each time the invoice is read.
4. Extend `formatCents` in `src/util/money.js` to take a currency and print the right symbol and two decimal places (`€12.34`, `£12.34`, `¥12.34`).
5. Pass the invoice's currency through to the payment gateway call in `src/services/payments.js`.

## Acceptance criteria

- An invoice created with `currency: 'EUR'` is returned with that currency and its total in euro cents.
- Every invoice includes `totalUsdCents`.
- `formatCents(1234, 'EUR')` returns `€12.34`.

## Verification

Add tests for the new `formatCents` behaviour and for `usdEquivalent` with a stubbed rate. Run `npm test`.
