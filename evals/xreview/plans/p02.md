# Plan: paginate the invoice list

## Goal

`GET /invoices` returns every invoice the caller may see, which is slow and heavy for customers with a long history. Add paging so clients can fetch the list in pages.

## Approach

1. Accept two optional query parameters on `GET /invoices`: `page` (1-based, default 1) and `limit` (default 20).
2. In `src/services/invoices.js`, keep `list()` sorting by `createdAt` ascending and add a `listPage(page, limit)` that slices the sorted array from `(page - 1) * limit` for `limit` items.
3. In `src/routes/invoices.js`, filter to the caller's invoices first (admins see all), then apply the page slice. Parse the query string from `req.url`.
4. Respond with `{ items, page, limit, total }`, where `total` is the number of invoices the caller can see.
5. Document the two parameters in the README.

## Acceptance criteria

- With no parameters the response holds the first 20 invoices, oldest first.
- `page=2` returns the next 20.
- `total` equals the number of invoices the caller can see, and a customer never sees another customer's invoice on any page.

## Verification

Add `test/pagination.test.js` that creates 45 invoices and checks the sizes of pages 1, 2 and 3 and the value of `total`. Run `npm test` and confirm it passes.
