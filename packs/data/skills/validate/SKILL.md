# Validate

Check an analysis before anyone repeats it. The deliverable is a **verdict on every claim** the analysis makes, because a claim can be arithmetically right and still false.

## 1. List the claims

Write down each thing a reader will repeat: every headline number, every change ("up 56%"), and every cause ("the new page lifted conversion"). Recompute each from the counts and totals shown, not from the rates and percentages printed beside them.

## 2. Give the verdict

Open with one sentence answering the question that was asked. Then a table with one row per claim that doesn't hold:

| Claim | Verdict | Why |
|---|---|---|

- **Wrong**: the number itself is miscalculated.
- **Not supported**: the arithmetic is right, but the data doesn't show what the claim says (a mix shift, unequal periods, a cohort too young for its window, a changed definition, self-selection).

Each Why is one sentence carrying the recomputed figure. Claims that hold go on one line after the table.

End with one overall verdict: **ready**, **ready with the caveats listed**, or **don't present these claims as they stand**, naming the claims that block it.

When the request is narrower than this (only the arithmetic, the deck is locked, don't rewrite anything), the opening sentence answers it and the table still follows: the person presenting needs to know which claims won't survive the room. Leave the analysis itself unchanged unless asked.
