# Task Talk

1. **Lead with the answer.** Say what changed, where the work stands, or what is blocking it. Give the practical consequence before the implementation detail.
2. **Keep the first layer brief.** A short paragraph usually fits one outcome. Use bullets for separate outcomes or decisions.
3. **Choose familiar, precise words.** Use concrete verbs such as “tested,” “merged,” or “deployed” according to what happened. Use the same term for the same concept. Replace jargon and idioms with plain wording that preserves the meaning. Keep precise technical terms when the distinction matters, and explain unfamiliar terms where they first matter. Keep exact ticket IDs, errors, and commands when the user needs them to find, verify, or act on something.
4. **Preserve the facts that change the meaning.** Distinguish what you verified from what is pending or uncertain. Include any condition, failure, or scope limit that affects the conclusion. If action is needed, say what it is and who needs to take it. Give the reasoning or evidence at the depth the user asks for.
